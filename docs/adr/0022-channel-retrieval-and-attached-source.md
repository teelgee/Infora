# ADR-0022 - Retrieval is a separate pipeline per channel and per grounded corpus, with access resolved before search; the project library is searched hybrid (vector + code) over its single live version per container, the authority corpus searched public and licence-gated; a user-attached-source mode lets the user pin a specific document, reconciling sandbox use with ADR-0011

**Status:** Accepted. Builds on ADR-0011 (AI never grounds on the sandbox), ADR-0013 (supersede/withdraw leave the grounded corpus), ADR-0020 (three stores; access-resolved before retrieval) and ADR-0021 (the three channels; the grounded channel's two corpora).

**Context:** With the channels defined (ADR-0021), retrieval had to be specified. The live questions: one merged index or a pipeline per channel; how to keep ADR-0020's access-resolve-before-retrieval guarantee; how to honour that construction deliverables are identified and referred to by code, not just by meaning; how the grounded channel's two corpora — the project library and the authority corpus — differ at retrieval, given one is access-resolved and project-private and the other public and cross-project; and how the everyday workflow of pointing an agent at a specific sandbox file — an Excel of calculations, a draft — squares with ADR-0011's rule that the AI never grounds on the sandbox.

**Decision:** Retrieval is a **separate pipeline per channel, and per corpus within the grounded channel**, not one search over a merged index, because the channels and corpora differ on access scope, citability and selection logic; merging would either lose the pre-search access filter or let private informing material fall into a citable slot.

**Grounded channel — project library.** Access-resolve to the requester's permitted library slice first, then search that slice **hybrid**: semantic vector recall plus lexical match on the deliverable code and metadata. Hybrid rather than pure vector because a coded reference is a near-meaningless token to an embedding model, yet code is how this domain names documents; and because the structured filtering below is required anyway, so lexical code match reuses infrastructure that must exist. Two hard state rules bind: superseded and withdrawn deliverables are excluded (they are in the library but out of the grounded corpus, ADR-0013); and the corpus holds exactly **one live version per container** by construction, so retrieval never surfaces or cites a v1 while a v2 exists. No trust tier inside the corpus: accepted deliverables and owner-added reference material rank equally, since both are already trusted by being in the library.

**Grounded channel — authority corpus.** Searched as a public, cross-project corpus with **no per-organisation access resolution** — the law is the law — so its candidate set is not filtered by the ethical wall. A **licensing gate** instead governs licensed standards (an entitlement check, distinct from the wall). Cited as external authority, never as project fact, so its results are kept distinct from library results even though both back citations. Its currency — which version of a statute or standard is in force — is a concern of the authority register, now owned within Context (ADR-0023, as revised), and is not settled here; this ADR fixes only that it is a second, separately access-governed grounded pipeline.

**Informing channel.** Semantic-led retrieval over the requester's *own* org and programme context, matching a precedent or approach by resemblance rather than by code. Never merged with the grounded slice.

**Guiding channel.** Not similarity-retrieved as a whole: guardrails are always-on, compiled into the Rail at generation time, and templates and style are selected by the task — the deliverable's type picks its template — rather than ranked by similarity to the query.

**Attached source.** Alongside channel retrieval (where the system chooses what to pull) there is a user-driven mode: the user explicitly pins a specific document — including a sandbox file — as a direct input to a single generation. This reconciles the sandbox workflow with ADR-0011: the AI never *automatically* grounds on the sandbox, but a user may hand it one file and take the trust onto themselves. The attached source is scoped to that input and ephemeral to the task, never joins any corpus, and is shown with a visible user-supplied marker — never a grounded library citation — so the trust distinction stays honest and the audit records who vouched for it.

**Consequences:** Three retrieval pipelines plus an attachment path, rather than one index, is more surface to build but is what keeps the access-resolve-before-search guarantee and the no-leak property intact at the retrieval layer rather than relying on output-time filtering. Hybrid grounded search needs a structured metadata layer (code, type, status, version) beside the vectors; that layer is mandatory for the state rules regardless, so the marginal cost of lexical code match is small, and it is the right build-1 choice rather than a later optimisation. "Use latest version" and "exclude superseded" are one rule seen from two ends, both falling out of ADR-0013, so retrieval enforces currency simply by filtering on live state. The attached-source mode opens a user-directed path to sandbox material without weakening ADR-0011, at the cost of a second citation status (user-supplied versus grounded) that surfaces must render distinctly. Leaves open precedent selection within the informing channel and the long-term store and embedding choice.
