# The document-management and AI-context landscape — researched 2026-10-23

**What this is, in plain terms.** Before judging whether Infora's project library, sandboxes and context layer are as good as they could be, we looked at what the best products in four neighbouring families actually do today. This file is the evidence. It is context, never authority: nothing here is a decision, and no ADR should cite it as a reason. The review that reads it is [dms-context-review.md](dms-context-review.md).

**How it was gathered.** Eight research passes on 2026-10-23: four, one per family in §§1 to 4; then, at the owner's direction the same day, four more sweeping the AI-native startup cohort and the everyday tools a pilot user already has open, recorded in §8. Each read vendor documentation, release notes, press, forums and review sites, with every fact carrying its URL and a source type. The passes were run by a smaller model and then read, cut and arranged by the reviewing model; the raw notes are longer than this file and were not kept in the repo. Facts marked *via search summary* were seen only as a search-engine excerpt because the page refused to load (G2, Capterra, the Autodesk Community, Dalux support, Harvey release notes, several vendor blogs all returned 403 or need a login). **Re-fetch anything so marked before quoting it to a customer.** No Reddit or LinkedIn thread was retrievable at all, so the complaint evidence is directional, not representative.

**What it supersedes.** This file is now the benchmark for document-management and context decisions. [ProjectWise-AssetWise-Competitive-Friction-Map.md](ProjectWise-AssetWise-Competitive-Friction-Map.md) is retained for two things this file does not repeat: its Part 1 list of incumbent primitives worth keeping, and its TYLin deployment-site evidence (the how-to articles that map where the incumbent hurts). [nomic-docs-review.md](nomic-docs-review.md) stays the Nomic authority; §3.1 below records only what changed after it was written. [legora-ui-review.md](legora-ui-review.md) and [ontology-landscape.md](ontology-landscape.md) stand; §4 and §2.3 point into them rather than restate.

## 1. The construction CDE incumbents

### 1.1 Oracle Aconex

- **Organisation-owned registers plus transmittals.** Each organisation has its own document register; another organisation sees a document only when it is sent in a transmittal. [vendor docs, via search summary] https://help.aconex.com/mail/who-can-see-my-mail-and-documents/
- **A sent transmittal cannot be edited or recalled**; Aconex keeps it permanently in the project record. [vendor docs] https://help.aconex.com/documents/transmit-your-document/
- **Supersession is a transmitted event.** "No Longer in Use" removes a document from the marking organisation's register, keeps it in History, and cannot be reversed; other organisations keep their active copy until a transmittal carrying the no-longer-in-use version reaches them. The number cannot be reused until every holder has received it. [vendor docs] https://help.aconex.com/DisplayContent/mark-document-as-no-longer-in-use
- **Review status labels are set by the project owner organisation**, so they differ per project; each markup can carry its own status; submitting markups one by one creates a workflow transmittal each. [vendor docs, via search summary] https://help.aconex.com/workflows/mark-up-changes-to-a-document-in-a-workflow-step-using-the-online/
- **Register search exposes review facts** (review status, workflow number, markup count, markup last-modified) with search codes such as `hasmarkups:` and `markupcount:`. [vendor docs, via search summary] https://docs.oracle.com/en/industries/construction-engineering/intelligence/subject-area-reference-guide/aconex-documents.html
- **April 2026: a Review Matrix** starts the sign-off route from document metadata in a pre-agreed sequence, and integrated comment management replaces offline spreadsheets. Announced 13 April 2026; no configuration or availability detail; press framed it as "AI", Oracle did not. [vendor press] https://aijourn.com/new-oracle-aconex-capabilities-improve-project-transparency-and-control/
- **Permissions.** Default visibility is the whole uploading organisation; a user with "Edit document confidentiality" can restrict a document to a named list; an org setting can make every upload confidential by default; access-control rules can hide an attachment while its transmittal stays visible. [vendor docs, via search summary] https://help.aconex.com/documents/uploading-confidential-documents/ and https://help.aconex.com/org-admins/use-access-control-to-restrict-users-access-to-documents/
- **Daily UX.** Register-first and search-driven, not a folder tree; a missing menu item usually means a missing permission. [vendor docs] the pages above.
- **Complaints (all via search summary of review sites).** "Dated" interface and "steep learning curve"; slows with large document volumes; password-expiry resets every three months; limited reports. https://www.capterra.com.au/reviews/118711/aconex ; https://www.trustradius.com/products/oracle-aconex/reviews ; https://www.g2.com/products/oracle-aconex/reviews
- **AI.** None marketed natively as of October 2026. [third party] https://www.constructionindustry.ai/tools/project-management/oracle-aconex/ . Datagrid (now owned by Procore) sells agents that extract document type, discipline and revision from Aconex content. [third party] https://datagrid.com/integrations/oracle-aconex

### 1.2 Autodesk Construction Cloud (Docs is now "Forma Data Management")

- **Folder-based; folders and files are both containers; folders carry custom attributes**, which Manage-level members can make required. **ISO 19650 naming-standard folders force the naming attributes and block their removal once added.** [vendor docs, via search summary] https://help.autodesk.com/view/DOCS/ENG/?guid=Folder_Level_Attributes
- **Approval workflows copy approved files to a target folder** (naming-enforced if wanted) and stamp Status and Revision automatically. Same page.
- **The ISO 19650 gap, in the vendor's own forum.** One user's idea post, about two and a half years old, says ACC has no native way to tie permissions to WIP, Shared and Published, so teams build separate WIP and Shared folders per role, which duplicates files and moves them folder by folder. [forum, one post, via search summary] https://forums.autodesk.com/t5/acc-ideas/implement-a-real-and-functional-iso-19650-workflow-for-file/idi-p/12560053 . **Autodesk's answer, "Smart Controls"** (metadata such as approval status managing access automatically), is future tense in a 15 September 2026 post with no date. [vendor press] https://adsknews.autodesk.com/en/news/autodesk-forma-ai-aec-connected-workflows-2026/
- **Permissions are per folder** on a View, Create, Edit, Manage ladder; members can be assigned by company. [vendor docs, via search summary] https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/How-to-assign-permission-by-company-for-project-members-in-ACC.html
- **Bulk attribute edit** on a selection, with a same-number or sequence option for numeric fields. [vendor docs, via search summary] https://help.autodesk.com/cloudhelp/ENU/Docs-Files/files/file-folder-actions/Edit_Attribute_Values_Docs.html
- **Non-compliant values after a rule change are highlighted yellow in the file list** and must be fixed by hand. [vendor docs, via search summary] https://help.autodesk.com/cloudhelp/ENU/Docs-Files/files/file-attributes/Create_Manage_Custom_Attributes.html
- **Forum asks:** custom attributes visible in Transmittal and Review views; bulk delete of attribute values. [forum, via search summary] https://forums.autodesk.com/t5/forma-for-construction-ideas/attributes-bulk-edit-delete-add/idi-p/13855276
- **AI.** Autodesk Assistant answers questions over published specifications with highlighted, clickable references into the spec text; its release stage is reported inconsistently (beta in one 2026 overview, generally available in a later post). [vendor press, via search summary] https://www.autodesk.com/blogs/construction/gcs-meet-autodesk-assistant-a-smart-tool-that-can-help-you-find-answers/ . January 2026 added meeting minutes as a source (via search summary). At Autodesk University (15 September 2026) a next-generation Assistant was previewed, not released: Assistant Spaces (a shared investigation room for people and agents), Assistant Builder, an AI Orchestrator choosing models by accuracy, speed, security and cost, Drawing Change Analysis, a Drawing Compliance Review planned for early 2027, and a standalone product with pricing "announced in 2027". "AI Transparency Cards" publish data sources, safeguards and known limits. [vendor press] https://adsknews.autodesk.com/en/pressrelease/autodesk-advances-agentic-ai-in-its-three-industry-clouds/ . BSI Kitemark for ISO 19650 claimed. [vendor press] https://www.autodesk.com/blogs/construction/driving-digital-standards-autodesk-construction-cloud-achieves-bsi-kitemark-certification-for-iso-19650/

### 1.3 Bentley ProjectWise (and ProjectWise 365, Bentley Infrastructure Cloud)

[vendor docs, via search summary] https://docs.bentley.com/LiveContent/web/ProjectWise%20Administrator%20Help-v12/en/GUID-687490C3-E625-364B-333F-5E8FC75D9C5A.html

- **Complaints.** A Revit file taking "15 to 20 minutes" to appear in the register; slow drawing opens; repeated logins (likely on-premises). [review site, via search summary] https://www.g2.com/products/projectwise/reviews . [forum] https://projectwiseweb.ideas.aha.io/ideas/PWWEB-I-41

### 1.4 Asite

- **Purpose of Issue and Status are separate drop-downs on each revision**, both lists defined per project; statuses can change conditionally and through workflows. [vendor docs, via search summary] https://help.asite.com/en/articles/5447536-define-file-statuses-in-a-project ; https://help.asite.com/en/articles/5508918-conditional-status-change
- **Each status carries an access level (No Access, Access to Use, Admin) per user, role or organisation**; new statuses default to no access except for the creator and the workspace admin. So "who may set this status, and who may use a file that carries it" is a first-class setting. [vendor docs, via search summary] same help set.
- **Templates carry folders, permissions and workflows; "you can't break inheritance on a single folder."** [vendor docs, via search summary] https://help.asite.com/en/articles/6855895-projects-faqs
- **The 2026 change log shows enforcement by script.** Folder-level title uniqueness across revisions and placeholders (29 March 2026); current attributes embedded in downloaded DOCX/XLSX and in PDFs on view; Word and DWG metadata sync; automated revision sync for O&M documents; bulk removal of associated items; import/export of project attributes; shareable saved filters by QR code or link (1 February 2026); private comments shareable to chosen users, roles or organisations (8 March 2026). **Most are Groovy scripts run by System Tasks, so admins write code.** [vendor docs] https://help.asite.com/en/articles/13595753-new-features-enhancements-2026
- **Complaints (via search summary).** A document controller could not correct a wrong reference number on forms and was asked for a fee; "very difficult to use as a supplier"; "sometimes it crashes"; busy dashboard after the move from Classic, with some tasks still needing Classic. https://www.capterra.com/p/132369/Adoddle/reviews/?page=2 ; https://www.capterra.co.uk/software/132369/adoddle ; https://www.softwareadvice.com/rfp/adoddle-profile/reviews/

[vendor docs] the 2026 change log above.

### 1.9 ISO 19650 practice and the delivery-planning tools

- The repo's own digest is [iso-19650.md](iso-19650.md) and is the authority on the codes; the research pass found the status-code tables **conflict across free web sources**, which that digest already warns about. [third party, via search summary] https://graitec.com/uk/blog/iso-19650-revision-2026/

## 2. Enterprise AI context layers

**The one sentence that matters.** Nearly every product in this family answers "what may the assistant know?" with "whatever the user can already open", then bolts curation on top. **None separates "may steer" from "may ground"**: no product lets private organisational knowledge shape an answer while being barred from backing a cited claim. That is an absence in the documentation read, not a proof, but it is the gap Infora's channel rule sits in.

### 2.1 Microsoft 365 Copilot (now "Microsoft Copilot")

- **Default: everything the user can open is eligible.** Copilot "only surfaces organizational data to which individual users have at least view permissions"; the semantic index "honors the user identity-based access boundary". The page does not say whether trimming is before or after the vector match. Guests reach whatever inter-tenant sharing already granted; there is no separate wall for AI. [vendor docs] https://learn.microsoft.com/en-us/microsoft-365/copilot/microsoft-365-copilot-privacy (updated 2026-10-08)
- **Curation is by shrinking the haystack, and Microsoft calls its own tools temporary.** Restricted SharePoint Search "is retiring. Starting July 31, 2026, new enablement is blocked", and "isn't a security boundary". [vendor docs] https://learn.microsoft.com/en-us/sharepoint/restricted-sharepoint-search . Its replacement, Restricted Content Discovery, hides a site from Copilot but "doesn't remove content from the Microsoft 365 search index", can take over a week on large sites, is "a temporary governance control", and **requires a justification from the admin who flips it, logged to Purview**. [vendor docs] https://learn.microsoft.com/en-us/sharepoint/restricted-content-discovery (updated 2026-10-11)
- **A pinned source set exists only in Copilot Notebooks:** "uses only this curated content" and does not reach OneDrive, mail, chats or the web; up to 300 files; a shared location contributes "up to 300 of the files you can access that are most relevant", so a file must be added directly to be guaranteed. [vendor docs] https://support.microsoft.com/en-us/microsoft-365-copilot/how-microsoft-365-copilot-notebooks-works
- **Labels follow the output.** The response and its citations show the highest-priority sensitivity label among the sources; a draft inherits it; encrypted items without EXTRACT or VIEW rights are not returned. [vendor docs, via search summary] https://learn.microsoft.com/purview/ai-m365-copilot . **It failed in practice:** bug CW1226324 let Copilot summarise labelled, DLP-covered emails from Sent Items and Drafts from 21 January 2026 until a fix began in early February. [press] https://bleepingcomputer.com/news/microsoft/microsoft-says-bug-causes-copilot-to-summarize-confidential-emails
- **Audit.** Each interaction stores the prompt, the response and "citations to any information used", searchable by admins under retention policy. [vendor docs] the privacy page.
- **Complaints.** "Very frequently the citations given by Copilot, both inline and in the final Sources section will be incorrect", and a corrected answer "still contains exactly the same citation". [forum, 2026-02-19] https://learn.microsoft.com/en-us/answers/questions/5780642/citations-consistently-wrong-in-m365-copilot-(bizc . "Most corporate implementations of network roles and permissions are not up to date or accurate." [forum] https://news.ycombinator.com/item?id=41328133 . "Really Microsoft should be auditing the search that copilot executes, its actually a bit misleading to be auditing the file as accessed." [forum, an allegation] https://news.ycombinator.com/item?id=44957454
- Copilot Studio agents list knowledge sources per agent or per node and carry an "Allow ungrounded responses" switch. [vendor docs, via search summary] https://learn.microsoft.com/en-us/microsoft-copilot-studio/knowledge-copilot-studio

### 2.2 Glean

- Index everything the user can see across "275+" connectors (a marketing figure); "Glean mirrors the permissions in your connected apps" and, per the indexing SDK docs seen via search, "enforces permissions at query time" from connector-supplied ACLs. [vendor marketing; vendor docs] https://docs.glean.com/user-guide/about/end-user-quick-start-guide ; https://developers.glean.com/libraries/indexing-sdk/permissions
- **The only real "verified by whom, when" loop in the family.** A verified document is "personally approved by one of your users that it's accurate and up to date"; it gets a green badge; hover shows who and when; the owner can set a re-check reminder that returns the document to their task list; anyone can "Request verification"; owners can filter unverified, verified and deprecated; an API accepts VERIFY, DEPRECATE and UNVERIFY. **The docs do not say whether verification or deprecation changes ranking.** [vendor docs] https://docs.glean.com/user-guide/knowledge/verification/how-verification-works ; https://developers.glean.com/client/operation/verify
- Memory (October 2026): activity-based and saved memories, with an org-wide admin switch and user-level management; agent memory is a separate "notebook" per step. [vendor docs] https://docs.glean.com/release-notes/releases/2026-10-08-october-release ; https://docs.glean.com/agents/concepts/memory
- Complaints are second-hand and mostly competitor-written: 3 to 6 month rollouts, "tricky setup" where "a small misconfiguration could potentially expose sensitive information", find-not-act. [review/blog] https://workativ.com/ai-agent/blog/glean-review . Single-company product; no multi-organisation handling found.

### 2.3 Palantir AIP and the Foundry Ontology

The repo's [ontology-landscape.md](ontology-landscape.md) covers the ontology as a modelling idea. What this pass adds is **who confirms a change**, which Palantir answers better than anyone else read.

- **Changes to the model go through proposals "analogous to a Pull Request".** Branch protection is on by default for Ontology Manager resources; reviewers approve or reject per task; approvers generally must be editors or owners of the affected resource; merged proposals cannot be reverted automatically. Global Branching became generally available 18 May 2026. [vendor docs] https://www.palantir.com/docs/foundry/ontologies/review-ontology-proposals ; https://www.palantir.com/docs/foundry/announcements/2026-05
- **The world changes only through a named, logged action.** "Ontology edits only happen through actions"; each action type can write a log object per submission linked to every object it edited, with user and timestamp. [vendor docs] https://www.palantir.com/docs/foundry/functions/edits-overview ; https://palantir.com/docs/foundry/action-types/action-log/

## 4. Interface patterns from adjacent professional software

The repo's [legora-ui-review.md](legora-ui-review.md) already records the Legora patterns (three-zone layout, plan-approval card, run checklist, citation chips with hover source cards, per-suggestion Apply and Dismiss, avatar stacks and live selections). This pass adds the following.

### 4.1 Harvey

- **Scope the question by choosing sources** before it is answered; listed sources include Vault, legal databases and web; "nudges" suggest the best context. A search result says up to two knowledge sources per prompt, permission-dependent. [vendor docs] https://help.harvey.ai/articles/getting-started-with-harvey ; [via search summary] https://help.harvey.ai/articles/knowledge-sources-overview
- **Vault** holds up to 100,000 files, syncs from iManage, SharePoint and Google Drive, and offers Review Tables that extract data points across many files into a grid; the Library holds Workflows, Review Tables, Prompts, Playbooks and Examples, some Harvey's, some the admin's, some yours. [vendor] https://www.harvey.ai/platform/vault
- **Location equals visibility.** Review tables inside a vault inherit the vault's sharing; a table outside it is shared by its owner; moving it into a vault needs edit access; owners can stop view-only users downloading, duplicating or seeing the prompts behind a table (release notes 2026-01-28 and 2026-07-07, seen as snippets because the page needs a login). https://help.harvey.ai/release-notes/moving-and-sharing

[vendor] https://linear.app/changelog/2019-08-04-filters . **The 2024 redesign** cut visual noise, moved properties to a side panel and filters to the header, left navigation unchanged on purpose, and rolled out by private beta then a daily percentage of workspaces. [vendor] https://linear.app/now/how-we-redesigned-the-linear-ui
- **Command palettes are criticised mainly for discoverability**; a palette should supplement visible navigation with a visible hint. [third party] https://uxpatterns.dev/patterns/advanced/command-palette ; one teardown says Notion's palette finds pages but few actions while Linear users expect actions. [opinion] https://www.setproduct.com/blog/command-palette-ui-design-guide

- **Figma:** "Review and merge changes" opens one dialog to pick reviewers and add a note; status badges "In review", "Changes suggested", "Approved" sit beside the branch name; the review window lists changes grouped by page with side-by-side or overlay comparison; **decisions apply to the whole branch**, review is optional and does not block merge. [vendor] https://help.figma.com/hc/en-us/articles/5691414603543-Request-a-branch-review ; https://help.figma.com/hc/en-us/articles/5693123873687-Review-branch-changes

[vendor] https://support.google.com/docs/answer/190843 ; https://support.google.com/docs/answer/6239410
- **Word:** accept all shown, accept all, accept all and stop tracking; filtering by reviewer then accepting all shown is described only by a third party. Hiding markup does not remove it, a known trap before sending. [vendor, via search summary] https://support.microsoft.com/en-us/word/training/accept-tracked-changes

### 4.4 GitHub pull requests and Google Docs comments

- **GitHub:** a review ends with Comment, Approve or Request changes; per-file "Viewed" collapses the file and drives a progress bar; "Request changes" is advisory unless branch rules require reviews; a Conversations menu lists threads as unresolved, resolved or outdated. [vendor, via search summary] https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests/reviewing-proposed-changes-in-a-pull-request
- **Google Docs comments:** anchored to selected text; open or resolved filter; assigned action items with Done and an open count; keyboard R reply, J/K next and previous, E resolve; a per-file comment cap. [vendor] https://support.google.com/docs/answer/65129

### 4.5 File registers and bulk actions

- **Dropbox Dash Stacks:** a set assembled in seconds, with grid and list views, inline previews, "who added this and why", a sidebar chat, typeahead filters, a keyboard launcher. **Files added to a Stack are shared automatically**, which is the wrong default across organisations. [vendor] https://dash.dropbox.com/release-notes
- **Box metadata:** templates applied to a selection with explicit modes (Append, Replace, Clear All, Remove Entered, Replace Entered); folder cascade policies push values down. [vendor, via search summary] https://support.box.com/hc/en-us/articles/37601715340435-Managing-Metadata-in-Box-Apps
- **Nielsen Norman Group on bulk actions (17 March 2025):** offer select-all, show a contextual action bar on selection, give feedback and undo. https://www.nngroup.com/videos/bulk-actions-design-guidelines/ . **On data tables:** the four tasks are find, compare, edit one row and act; filters must be discoverable, quick and powerful with a clear sign that they are on; freeze headers; make the first column a readable name. https://www.nngroup.com/articles/data-tables/
- No primary source was found for hover previews, upload progress or inline rename in Egnyte, Box or Google Drive; do not cite them.

### 4.6 Writing-tool AI

- **Grammarly:** underlines coloured by category, cards on the right, click jumps to the text; **bulk accept appears only when three or more suggestions pass a confidence bar**, with a preview, whole-batch undo and per-item revert, because people accept spelling fixes often and tone fixes rarely. [vendor, 2021-03-31] https://www.grammarly.com/blog/engineering/accepting-multiple-suggestions/
- **Vale:** error, warning, suggestion; a minimum-level setting hides lower ones; editor plugins show counts in the status bar. [third party, via search summary] https://www.obsidianstats.com/plugins/vale-linter
- **Cursor:** in May 2026 users complained that the agent now applies edits first and offers one session-level "Review +1181 -413" button, losing per-change Accept and Reject; staff replied that per-change controls still exist but the default shifted. **Per-change approval before write is a trust feature people notice when it goes.** [forum, 2026-05-17] https://forum.cursor.com/t/bring-back-per-change-apply-inline-diff-review-you-re-throwing-away-your-best-ux-advantage/160856

### 4.7 Published research on citations and complex applications

- **Citations raise trust even when the sources are wrong or fabricated**, and showing model confidence lowers trust; higher trust predicts more clicking and less time evaluating. Li and Aral (2025), "Human Trust in AI Search: A Large-Scale Experiment". https://arxiv.org/abs/2504.06435 (abstract read)
- **Only 22% of conversations were followed by a check** in a Nielsen Norman Group diary study (18 participants, 425 conversations, 2023); people checked more when stakes were high, and checking had a high interaction cost. https://www.nngroup.com/articles/generative-ai-diary/
- **A source card list was noticed in about one second, bare links in about sixteen**; a side panel held attention longest; inline chips were most often named best in interviews; survey ratings showed no significant difference between layouts (23 students, simulated screens, one topic; the page was read in part). https://pmc.ncbi.nlm.nih.gov/articles/PMC13513764/
- **Complex applications:** show steps and time estimates for waits over about ten seconds; add accelerators for experts and wizards for novices; automatic version history with restore; test with domain experts on real material. Nielsen Norman Group, 2021 and 2025. https://www.nngroup.com/articles/usability-heuristics-complex-applications/ ; https://www.nngroup.com/articles/strategies-complex-application-design/

## 5. What best in class looks like, consolidated

Each practice names who does it best and where the evidence sits above. The review measures Infora against this list; this file only records it.

**Record and control**

1. **Status is an access boundary, not a folder convention.** Access per workflow state (ProjectWise §1.3); per-status access by user, role or organisation (Asite §1.4). The counter-example is ACC's forum (§1.2).
2. **Required naming and metadata that cannot be switched off**, with non-compliant values flagged in place after a rule change (ACC §1.2; Asite title uniqueness §1.4).
3. **A permanent, unrecallable transmittal record**, and supersession as an event the other party must receive (Aconex §1.1).
4. **Review routing from metadata** in a pre-agreed sequence (Aconex Review Matrix §1.1, announced).
5. **Approved copies land in a controlled place with status and revision stamped automatically** (ACC §1.2).
6. **A review package that respects per-document access and recalculates progress** per viewer (Procore §1.6).
7. **Saved views instead of folders**, shareable by link (Procore §1.6; Asite §1.4; Linear §4.2).
8. **The TIDPs and the MIDP are one record**, so they cannot drift (Plannerly), and the plan is linked to the register, with status updated from submissions and dashboards by discipline, originator and milestone (Morta, both vendor claims §1.9).
9. **Bulk attribute edit with an explicit mode** (append or replace) and a sequence option (ACC §1.2; Box §4.5).

**Context and authority**

10. **A pinned set the product states is the only source**, with an honest size ceiling (Copilot Notebooks, Gemini Notebook, Box Hubs §2).
11. **Curation as a staged pipeline with a human gate:** AI proposes tags, summary and a health score; a human approves and assigns an owner; stale items are re-flagged (Box §2.4).
12. **A visible "verified by whom, when" mark with a re-check clock and a deprecate action** (Glean §2.2).
13. **Changes to the shared model behave like pull requests**, approvers must own the affected resource, and the world changes only by a logged action with preconditions separate from permissions (Palantir §2.3).
14. **Agents act as the user, never above them** (Palantir, Copilot, ChatGPT, Harvey §2, §4.1).
15. **Output carries the label of its most sensitive input**, and drafts inherit it (Microsoft §2.1).
16. **Every interaction stored with the citations it used**, retrievable by admins (Microsoft §2.1; Box AI Activity §2.4).
17. **Visibility changes are justified and audited** (Microsoft Restricted Content Discovery §2.1).
18. **Instructions travel with the pinned set** (Claude Projects §2.6); house style applied before a reviewer sees the draft (Writer §2.5, marketing only).

**Provenance and AI output**

19. **Cite a retrievable source for every rule the model states, and never state numbers from memory**; label weak findings "potential"; confirm scope with the user before a large review (Nomic §3.1).
20. **Pin answers to the controlled version** (Document Crunch §3.3).
21. **Say "not in the documents"** rather than answer thin (Trunk Tools §3.2, review claim).
22. **Requirement-versus-status in one table**, drafted for a named human to verify (Procore §1.6).
23. **Show the cited passage beside the claim, make the check one click, and mark unsupported sentences**, because citations alone raise trust even when wrong (§4.7).
24. **Per-passage accept before anything is written**; selective bulk accept only for the safe class, with a confidence gate, preview and batch undo; severity filter with counts (Cursor, Grammarly, Vale §4.6).
25. **Log what the AI changed** so a person can review it (Bentley §1.3); publish transparency cards on data sources and limits (Autodesk §1.2).

**Working together**

26. **Location equals visibility, and the move warns you**; show who can see an item before it enters a shared space; never auto-share on add (Harvey §4.1; Dash as counter-example §4.5).
27. **A status badge beside the name carries the ready-for-review moment**, and one dialog requests review with a note (Figma §4.3).
28. **Per-file "Viewed" progress, a thread list of unresolved, resolved and outdated, assigned action items with an open count, and keyboard moves through comments** (GitHub, Google Docs §4.4).
29. **Named milestones in version history and a "changed since you looked" dot** (Google Docs §4.3).
30. **Guest access without a licence, and "share the tool, hide the prompt"** (Harvey Shared Spaces §4.1).
31. **Filters that belong to the view and work from the keyboard; properties in a side panel; quiet chrome; a command palette with a visible hint** (Linear §4.2).
32. **Steps and time shown for long AI waits; whole-batch undo; gradual rollout and testing with domain experts** (§4.2, §4.6, §4.7).
33. **Meet people where they work** (SMS and Teams, Trunk Tools §3.2; a Word task pane, Legora per [legora-ui-review.md](legora-ui-review.md)), and price by a visible unit of work (Nomic §3.1).

**From the second sweep (§8)**

34. **"No citation to the governing paragraph or sheet, no finding"**, and a second agent that tries to disprove each finding before it is shown (Specset §8.2).
35. **Every finding cites both sides**: the spec section and the sheet (Helonic), the drawing page and the code section (UpCodes Plan Review), the sheet reference plus an evidence snippet (InspectMind) (§8.2).
36. **A visible gap, not a guess.** The drafter leaves "TBC" where the sources do not answer (Avoice §8.1, vendor claim via search summary); the model "does not state numbers from memory" (Nomic, item 19).
37. **Citations are extracted, never generated.** The Claude Citations API returns the cited text verbatim with a page number and cannot cite a scanned PDF; Google's own help admits Gemini "may miss a source it used, cite one it didn't use for a specific claim, or occasionally invent a source"; Adobe's community manager says Acrobat drops citations when the question's language differs from the document (§8.6).
38. **AI authorship tracked on the drafted document**, with nothing finalised without a named human (Alloovium §8.1, vendor claim); a hard "stays a draft until a person approves" rule for anything an AI creates (Catenda AI Connect §8.5).
39. **The firm's own checklist drives the review** (UpCodes Plan Review; Buildcheck turns a QA playbook into agents §8.2), and **the firm's own template receives the draft** (Avoice "Practice Voice", Mastt, Specpoint office masters §8.1, §8.5).
40. **Name the weakness.** "Strongest on quantitative cross-references, weakest on intent and tone" (Helonic); accuracy stated by input quality, hand-drawn and pre-1975 PDFs harder (Civils.ai §8.2).
41. **Re-run on a new issue and isolate what changed** (UpCodes re-upload; Buildcheck changes between revisions; Bluebeam Smart Overlay; Aitenders version conflicts by clause §8.2, §8.5).
42. **A finding becomes an owned thing with a status**: one-click RFI (Helonic), a notice drafted from the clause that requires it and assigned (Telamont), issues assigned and tracked to resolution (Document Crunch, UpCodes) (§8.2).
43. **Show the working.** Speckle Intelligence's agent trace has an Inspect step with the actual query, status, row count and run time (§8.5).
44. **A table of what each AI feature does with data, and an off switch per feature**; AI off by default until an admin enables it per process (Bluebeam's AI transparency page; Oracle Unifier §8.5).
45. **Pin the edition to the project and show it on every answer** (UpCodes fixes jurisdiction and code year at setup §8.4); **a markup register whose status set the project defines**, filterable and exportable (Bluebeam Markups List §8.5).
46. **A private draft layer, then publish**; a review session with permissions fixed at creation and a chronological record linked to PDF locations (Drawboard; Bluebeam Studio §8.6); a pre-check the author runs repeatedly before the formal cycle (Archistar §8.4).
47. **The keystroke habits users arrive with:** "/" or "@" to pick a named file, a Sources list under every answer, a Keep / Discard / Regenerate choice before a draft lands, a "choose sources" switch (Word, Docs, Perplexity §8.6).

## 6. The frictions the families share

1. **Container states are bolted on.** Teams fake WIP, Shared and Published with folders and duplicate files; the fix is announced, not shipped (§1.2).
2. **Rules are hard to change after the fact.** Naming-standard edits disputed; changed rules leave old values for hand repair; "No Longer in Use" cannot be undone; inheritance cannot be broken on one folder (§1.1, §1.2, §1.4).
3. **Custom automation needs scripts** (Asite's Groovy System Tasks §1.4).
4. **Dated or busy interfaces and steep learning curves**; suppliers and external parties get a poor experience (§1.1, §1.4, §1.6).
5. **Speed collapses at volume or distance** (§1.1, §1.3).
6. **The AI wall is the source system's permissions, so bad hygiene becomes AI exposure.** Microsoft built one scoping tool, retired it, built another, and calls both temporary (§2.1).
7. **No product separates "may steer" from "may ground"** (§2).
8. **No product shows the user what was out of reach**; the answer just gets thinner (§2.1, §2.2).
9. **Citation accuracy is unreliable and unchecked**; document-level citation is the norm; passage-level is claimed by few and specified by fewer (§2.1, §3).
10. **Stale and superseded content has weak handling**; only Glean has an owner-driven verify-and-deprecate loop, and its docs do not say it changes retrieval (§2.2).
11. **Correcting a wrong answer is not a documented flow** anywhere except Palantir's reviewed edits (§2.3).
12. **Size ceilings clash with real project libraries** (300 files, 300 sources, 20,000 files and 2 MB per file, no spreadsheets or scanned PDFs §2).
13. **Multi-organisation walls are not a first-class idea anywhere.** Every AI tool is one firm, one tenant; the multi-company platforms (Autodesk, Procore) say little about how their AI respects cross-company boundaries; Harvey's Shared Spaces does not describe walls (§2, §3, §4.1).
14. **Announced is not shipped**, provenance is asserted in a sentence, and a platform owner can cut off a layer built on its data (§1.6, §3.4).
15. **Little on the producer side.** The sector's AI targets review, checking and risk; few tools help a consultancy produce a controlled deliverable through a cross-organisation review cycle (§3). **The second sweep confirms it:** of the roughly thirty products the startup sweep looked at closely, about twenty check someone else's drawings, specs or contracts, and the only drafters of a whole deliverable (Avoice, the spec editors) are single-firm spec tools (§8.7).
16. **The newest cohort is single-tenant by construction and is being bought by the incumbents.** None of the sixty-odd products describes several organisations on one project; the few boundary statements are single-tenant architecture (Primepoint), isolated environments per organisation (Structured AI) or row-level access (Howie). Bluebeam bought mbue, Trimble is buying Document Crunch, Procore bought Datagrid, Deltek added AI to its spec editor and RIB announced it (§8.7).
17. **"Bring your own AI" is spreading** (Bluebeam's and Catenda's MCP connections, TestFit's MCP connection, Revizto's announced MCP server, nPlan's connection to Claude and ChatGPT). It sends document text and markup data to an outside assistant under the user's own permissions, which on a walled project is a leak path unless the platform controls which assistants may connect and what they may read (§8.5).
18. **The everyday tools have taught users to distrust citations and to expect accept-all.** Word's accept is a paste unless Track Changes was already on; Docs' Refine is accept-all or reject-all; Acrobat, Gemini and Copilot all print "double-check" warnings (§8.6).

## 8. The 2025–2026 AI-native cohort, and the everyday tools

*Added the same day, at the owner's direction, from four further passes: the front-end agents (land, planning, permitting, code), the tools that produce, check and review deliverables, a sweep of the startup lists and portfolios, and the everyday tools a pilot user already has open. About sixty products were looked at; the ones that bear on Infora are below, with the rest named in §8.7. **The two sentences that matter.** The cohort confirms the market's shape: review dominates, production is rare and single-firm, and nobody has the wall. What it adds is a handful of rules worth adopting outright: "no citation, no finding"; a visible gap in a draft rather than a guess; citations extracted rather than generated; AI authorship tracked on the document; and a table saying what each AI feature does with data, with an off switch.

### 8.7 Patterns across the cohort, and the names checked and set aside

**Patterns.**

1. **Review, not production.** Of the roughly thirty products the startup sweep looked at closely, about twenty check someone else's drawings, specs or contracts; the only drafters of a whole deliverable are single-firm spec tools (§8.1).
2. **One agent per issue class, then a verifier.** Specset's disproving agent, Nomic's sub-agent per class, Buildcheck's reported human experts, Alloovium's sign-off: the convergent shape is find, try to knock down, then present.
3. **Grounding is the uploaded set plus a rule library, and nobody defines who may contribute to it.** The boundary statements that exist are single-tenant (Primepoint), isolated per organisation (Structured AI), seven-day deletion (Helonic), row-level access (Howie). **None describes several organisations on one project.**
4. **Provenance is converging on the sentence or the sheet, but few make it a rule.** Strongest: Specset, Alloovium, Helonic, Structured AI, Telamont. Almost nobody specifies "not found" behaviour; Avoice's "TBC" is the exception.
5. **Pricing by unit of work is the majority for review tools**: per drawing page and spec page (InspectMind), per sheet by scale (Civils.ai), per project (Provision, per a roundup), flat per firm (Marapone, unverified), and per-permit work as a reported signal at PermitFlow, whose pricing is not public. Seats are the minority (Part3, Nomic).
6. **Recurring interface shapes:** findings as clouds on the sheet with severity; a two-sheet overlay with opacity; one-click push to an RFI or a drafted notice; chat beside the document set; write-back to the source tool; an inspectable agent trace.
7. **The incumbents are buying the cohort** (mbue to Bluebeam, Document Crunch to Trimble, Datagrid to Procore, Consigli to AECOM), and **"bring your own AI"** is spreading (MCP connections at Bluebeam, Catenda and TestFit, an announced MCP server at Revizto, a Claude and ChatGPT connection at nPlan).
8. **Small teams, small rounds, vendor-made numbers.** Seeds of US$4 to 10M, Series A of 12 to 22M; at least eight YC companies reason over documents; every accuracy figure is the vendor's own.
