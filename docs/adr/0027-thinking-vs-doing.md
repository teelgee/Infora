# ADR-0027 - Thinking vs doing: deterministic-by-default, classified at the leaf at design time, the LLM compiles a rule into code once and the code runs it forever

**Status:** Accepted (promoted from placeholder 2026-07-01, the M2 grill). The principle was agreed in outline as a Session-3 offshoot; ADR-0028 (the orchestration/run/agent model) then fixed a concrete chain to classify, so the edges could be settled. Relates to ADR-0012 (component boundary / workflows), ADR-0023 (authority-register currency — the change-trigger for compiled compliance rules), ADR-0026 (codified workflows as a confidentiality-clean moat path) and ADR-0028 (the coded spine this constraint shapes).

**Context:** A foundational architectural constraint surfaced while settling how the moat compounds (ADR-0026). It governs how *every* workflow and capability is built, not just Context, so it is captured as its own ADR. The question is when to spend an LLM call and when to spend code: an LLM step that could have been code is wasted cost, latency and an avoidable point of non-determinism — and in a regulator-defensible system, non-determinism where a rule has a definite right answer is a liability, not a feature.

**The principle:** Classify every workflow step as **thinking** or **doing**.
- *Thinking* is genuine judgement-in-language — drafting prose, synthesising sources, interpreting ambiguous guidance — and belongs to the LLM.
- *Doing* is the execution of a stable, checkable rule — citation resolution, cross-reference validation, consistency checks, compliance gating against PINS/EIA requirements, format and register enforcement — and belongs to deterministic code.

Default to code wherever a step has a definite right answer. The LLM is the *compiler* that turns a rule into code once; the code is the *runtime* that executes it forever, at full accuracy and near-zero cost. The LLM is re-invoked only when the underlying rule changes.

**Decision:**

**1. Classify at the leaf, not the step.** Real steps are usually mostly-deterministic with a judgement residue. Decompose until each leaf is cleanly thinking or doing, then assign the leaf. A step is not "an LLM step" or "a code step" wholesale; it is a composition of leaves each routed to the cheaper correct executor.

**2. Two recurring patterns express every leaf composition.**
- **Code with an LLM escape hatch** — code settles the deterministic bulk and escalates only the genuine-judgement residue to the LLM. Use when the rule is mostly definite (e.g. reference validation that escalates an ambiguous match).
- **LLM with a deterministic verifier** — the LLM drafts, then code checks the result against a stable rule and can reject or constrain it. Use when the core act is judgement but the output must satisfy hard constraints (e.g. draft prose, then verify every citation resolves and no register/format rail is breached).

**3. Classification is a design-time act; run-time routing is deterministic.** *Who* decides thinking vs doing, and *when*, is settled: a workflow's leaves are classified **when the workflow or capability is built**, not re-decided per run. At run time the orchestrator does not ask an LLM "should this be code or a model call?" — it follows the fixed classification, which is exactly why ADR-0028's v1 chain is a **coded spine** (the ordering and the executor of each step are fixed in code; the only agentic freedom is *within* a thinking leaf). This keeps the audit trail's shape predictable and the routing itself free of model cost.

**4. Compiled rules carry versioning, provenance and a change-trigger (the currency loop).** A codified rule is a liability when the underlying requirement changes — stale deterministic code is confidently wrong. Every compiled rule is versioned, records the source rule it was compiled from, and is bound to a change-trigger that re-invokes the LLM compiler when that source moves. For compliance rules the trigger is the **authority register's currency** (ADR-0023): when the register updates a requirement, the rules compiled from it are flagged stale and recompiled.

**5. Codified rules encode the method, never a client constant.** A compiled rule is portable IP and confidentiality-clean only if it encodes *how* a thing is done, not a specific client's fact or figure (ADR-0026, Filter 2). Code's auditability — you can read exactly what a compiled rule does — is the advantage over model weights, and the reason codified workflows are a confidentiality-clean moat path.

**6. The v1 chain, classified.** Applying the above to ADR-0028's chain: `retrieve` = **doing** (query the Context gateway, deterministic); `draft` = **thinking** (the one genuine LLM leaf); `ground-check` = **doing** (a deterministic verifier over the draft — the LLM-with-verifier pattern, checking every claim resolves to a retrieved source and withholding what does not); `cite` = **doing** (citation resolution). One thinking leaf in a chain of doing — the concrete shape the constraint prescribes.

**Consequences:** Cost and latency fall to where the judgement actually is: one model call for the drafting leaf, code for the rest, rather than an agent "reasoning" through steps with definite answers. Determinism where it matters becomes structural — the ground-check and citation leaves are code, so "every grounded answer is verified and cited" is provable, not probabilistic (this is the machinery behind ADR-0028 §5's guarantee). The build gains an explicit obligation: every capability records, per leaf, its thinking/doing classification and — for doing leaves compiled from a rule — the rule's version, provenance and change-trigger. A currency debt is created and named: compiled rules must be recompiled when their source moves, and the authority register (ADR-0023) is the trigger source for the compliance family. The honest limit: leaf classification is a design-time judgement that can be got wrong (a "doing" leaf that actually carried judgement will be confidently wrong until reclassified); the mitigation is that mis-classification surfaces as a failing verifier or an escalation the escape hatch already routes to the LLM. Deterministic-by-default is now a build constraint the walking skeleton applies from the first chain, not a retrofit.
