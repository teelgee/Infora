# ADR-0029 - The Context→orchestrator assembly contract: one gateway call takes (request, environment, requester) and returns the access-resolved working input across channels; v1 merges grounded-first within a token budget

**Status:** Accepted (the M3 grill, 2026-07-01). Refined 2026-07-06: §5 gains the guiding-over-informing precedence on conflict — a semantic rule, not a budget order, that survives Session 6's re-ranking. Builds on ADR-0012 (Context owns assembly; the orchestrator calls it, does not reach stores), ADR-0020 (three scoped stores, per-request per-Participant assembly), ADR-0021 (the three channels), ADR-0022 (access-resolve before retrieve; per-channel pipelines), ADR-0025 (the assembly environment) and ADR-0028 (the orchestrator and its sub-agents retrieve *only* through this gateway). A thin, evolvable contract — the v1 slice of the full Session-6 ranking work, which stays deferred.

**Context:** ADR-0028 fixed that every retrieval — the baseline context a run opens with, and any targeted retrieval an agentic sub-agent issues mid-run — routes through Context rather than touching stores directly, so the ethical wall holds by construction. What it did not fix is the *shape of that call*: what the orchestrator hands Context and what it gets back. The skeleton's `retrieve` leaf cannot be coded without it. The full problem (channel ranking, budget optimisation, contextual retrieval, org-vs-programme precedence) is Session 6 and is deliberately out of scope; the MVP needs only a thin contract that is correct on access and good enough on merge, and can evolve behind a stable signature.

**Decision:**

**1. One gateway, one call signature.** Context exposes a single assembly call. **Input:** the **request** (the query or task text, plus a mode — see §4), the **environment** (a project key or a workspace key — ADR-0025, which sets the reachable channels), and the **requester** (organisation + Participant, the subject of access resolution). **Output:** the **assembled working input** — the selected content per channel (grounded / guiding / informing), each item carrying its source identity and channel so the caller can cite grounded items and never cite steering ones, all within a returned token budget. The orchestrator passes identity and intent; Context owns everything about *what is reachable and retrieved*.

**2. Access resolution runs inside the call, before retrieval.** The gateway resolves the requester's organisation, project role and entitled slice first, then retrieves only within what resolution admits (ADR-0022, ADR-0025). The orchestrator never sees, and cannot request, anything outside the environment's reachable, access-resolved set — there is no parameter by which a caller can widen scope. Grounding is safe by construction because the unreachable is never returned, not filtered out afterwards.

**3. Per-channel retrieval, assembled per request, never persisted.** Behind the one signature, each channel and grounded corpus is its own pipeline (ADR-0022): the project library and the authority corpus (grounded), the project's guiding material, and the requester's informing channel. The result is composed for this one request and returned; it is never stored as a merged artefact (ADR-0020).

**4. Two modes on the same signature.** *Baseline assembly* — called once at the start of a run to build the opening working input. *Targeted retrieval* — called by an agentic sub-agent mid-run to fetch additional material for a specific sub-question (ADR-0028 §4), folded into the calling agent's context. Both are the same call with the same access guarantees; they differ only in whether the request is the run's original task or a sub-agent's narrower query. This is what keeps agentic retrieval inside the wall.

**5. v1 merge: grounded-first within a token budget.** Within a fixed token budget the channels are concatenated in priority order — **grounded first** (project library, then authority corpus), then **guiding**, then **informing**. If the budget is exceeded, content is dropped from the **lowest-priority channel first** (informing → guiding), and grounded content needed to answer is never dropped in favour of steering material. No cross-channel relevance ranking, no org-vs-programme precedence, no contextual decomposition — a naive, predictable merge, explicitly a placeholder. This is acceptable for v1 because the skeleton is a single-consultant, single-project slice where grounded-priority concatenation gives correct, cited answers.

**Precedence on conflict (added 2026-07-06): guiding outranks informing.** Where the project's guiding material and an organisation's informing steer contradict — the owner's style guide mandates what the firm's house style forbids — **the project's guidance governs**, and the organisation's know-how fills in only where the project is silent. The reason is ownership of the record: the deliverable is produced for the owner's project record under the owner's guidance, exactly as rails carry the owner's ceiling (ADR-0030); a member's private steer improves its contribution but never overrides what the project has specified. This is a **semantic precedence, not a budget order** — it holds however Session 6 re-ranks retrieval and budgets, and assembly should state the rule to the generating agent (project guidance is authoritative; firm style is subordinate) rather than rely on concatenation order alone.

**Consequences:** The orchestrator's `retrieve` leaf (ADR-0028) becomes codeable against a stable signature, and because the signature carries no scope-widening parameter, the ethical wall is enforced by the contract's *shape*, not by caller discipline. The data model gains the call's inputs as first-class: every request carries an environment key and a requester identity that scope assembly before any store is read (already foreshadowed by ADR-0025). Each returned item's channel + source identity is what lets the `cite` leaf attach citations to grounded items only. The naive merge is a named debt: **Session 6** replaces §5 with real channel ranking, a tuned budget, org-vs-programme precedence and contextual retrieval, behind the same signature, so the upgrade does not ripple into the orchestrator. Honest limit: grounded-first concatenation can waste budget on low-relevance grounded chunks and under-serve a query that needs deep informing context — tolerable for the skeleton, not for the product, which is why Session 6 stays on the post-MVP list. May be superseded in part or folded into ADR-0022 when Session 6 lands.
