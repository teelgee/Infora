# ADR-0041 - Sandbox document versioning: a v0.x working series in the sandbox, P (preliminary) on formal issue or promotion, C (contractual) on client acceptance

**Status:** Accepted (owner-ruled 2026-07-25, sandbox-structure build session). Refines ADR-0032 (the P-rev/C-rev convention, freeze, ambient history) and ADR-0034 (renditions). Builds on the immutable-version rule (T-008, ADR-0013: `versions.version_reference` cannot change; only `is_current` may).

**Context:** Sandbox documents had no visible version numbers, and the two Version series ADR-0032 named ("the freeze series and the plan container's issued series") were both numbered informally — freeze wrote `P{n}`, promotion wrote `v{n}` — with no relationship to ISO 19650's revision codes (P = preliminary/work-in-progress, C = contractual/shared-and-published). The owner wants a real scheme the producing team recognises: working drafts run v0.1, 0.2, 0.3…; a version becomes a P or C revision when it leaves the informal sandbox.

**Decision — one working series, two issued series:**

**1. Whilst in the sandbox, a document runs the working series `v0.x`.** Every ambient save-snapshot is a working revision — `v0.1` the first, `v0.{n}` the current head (ADR-0032's ambient history). A **plain check-out freeze** (ADR-0032 addendum, T-180) freezes the current working revision under its own `v0.x` number: it is still sandbox-internal, not an issue.

**2. `P{NN}` — the preliminary issue.** A version earns a P revision (two-digit, per container) the first time it is **issued into a formal review cycle or promoted**: a freeze that opens an internal sandbox-scope round issues `P01, P02…` on the freeze container; a promotion issues `P01, P02…` on the library container (each client-review round a further P). "Promoted without review" is still `P01` — promotion is the issue event, review or not.

**3. `C{NN}` — the contractual issue on client acceptance.** When a client (project-scope) review cycle is **accepted**, the deliverable is authorised and published: acceptance issues the **contractual `C{NN}` revision** of the accepted content. Because `version_reference` is immutable (T-008/ADR-0013), C is a **new immutable Version** carrying the accepted content, made `is_current` — not a relabel of the accepted P. Retrieval, the library, the plan and renditions all key on `is_current`, so they read the published C revision with no further change; the reviewed P revisions keep their references as the record of each round. A sandbox-scope (internal QA) acceptance never issues a C — it is producer-private evidence, never contractual (ADR-0032).

**Consequences:** Freeze, promotion and acceptance assign references by phase, at issue, immutably. The sandbox document read carries a `workingRevision` (`v0.x`, resolved from the ambient count) and the ambient history carries `v0.x` per snapshot; the sandbox surface shows the working revision on each row. The freeze series and the issued series stay the two independent sequences ADR-0032 named — now ISO-19650-coded. **Consequence of the immutable-version rule:** a contractual acceptance adds one Version row (same content as the accepted P), which the idempotent ingest sweep indexes like any other; grounding stays single-current by `is_current`. **Deferred:** suitability codes (S0–S7) and the full ISO 19650 status matrix beyond the P/C revision letters; a per-issue suitability is a later refinement on this substrate.
