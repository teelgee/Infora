# ADR-0025 - Context is assembled within an environment: every request runs in exactly one environment — a project or an organisation's own workspace — and that environment, not the user's identity alone, sets which channels are reachable; the informing channel is portable, everything else is fixed to its environment, and access resolution runs before retrieval

**Status:** Accepted. Builds on ADR-0020 (three scoped stores; one working input per request), ADR-0021 (the three channels), ADR-0022 (access-resolve before retrieve) and ADR-0018 (the private floor). Sets the substrate for ADR-0026 (the distillation and egress boundary).

**Context:** ADR-0020 settled that one working input is assembled per request and per Participant, and listed what it draws on "for *this* project." Two things were left implicit, and Session 3's competing-clients confidentiality question made them load-bearing. First, the case where a request runs in an organisation's *own workspace* with no project attached was never defined — a consultant opening Infora to work on its own material, not inside any client project. Second, and more fundamental: ADR-0020 read as though the working input is a property of the *user* (their org, their role, the project's slice), when in fact the decisive control is *where the request runs*. A consultant serving rival clients A and B must, by construction, be unable to have A's grounded or guiding context reachable while it is working in B's project, or in its own workspace — and the thing that guarantees that is not a per-fact filter but the environment the request executes in. Filter 1 of the distillation boundary ("distil only from what you own, never from what you can merely see") is really a consequence of this same fact and should rest on it rather than be asserted separately. So the environment needs naming as a first-class primitive.

**Decision:** Every request runs in exactly one **assembly environment**, and that environment sets which channels are reachable.

There are two kinds of environment:

**A project environment.** A request made while working in a project P assembles: P's **grounded** channel — the project library (access-resolved to the requester before retrieval, so only the slice the requester is entitled to: its own authored deliverables plus what the owner has shared with it, never the whole library or another member's walled work) and the universal authority corpus; P's **guiding** channel — the project's shared templates, style guides and guardrails; and the requester organisation's **own informing** channel — its org context, including its custom workflows. If P belongs to a programme the requester's organisation owns, that programme's channels are reachable too, configured per project by the programme owner (ADR-0020, refined Session 3).

**The organisation's own workspace.** A request made in an organisation's workspace, with no project attached, assembles only that organisation's **own informing** channel (org context) and the universal authority corpus. There is no project grounding or guiding, because none is in scope: a workspace request cannot reach any project's library or guidance. This is the case ADR-0020 did not state.

Two invariants hold across both:

- **The informing channel is portable; everything else is fixed to its environment.** An organisation's org context travels with its Participants into every environment they work in. A project's grounded and guiding channels do not travel — they exist only inside that project. So a consultant in A's project reaches A's grounded and guiding plus its own informing; the same consultant in B's project reaches B's grounded and guiding plus the same own informing; in its own workspace it reaches only its own informing. A's grounded and guiding context is never reachable from B's environment or from the workspace, by construction.

- **Access resolution runs before retrieval, inside the environment.** Establishing the requester's organisation, project role and entitled slice happens first (ADR-0022); retrieval then draws only on what resolution admits. Grounding is therefore safe by construction within the environment, not patched at output time.

Sandbox privacy is a separate axis from channel reachability. A **private project sandbox** is hosted in its project's environment: a request made there reaches that project's grounded and guiding channels plus the requester's own informing, exactly as any project request does — the sandbox being private controls *who can see the work in it*, not *which channels are reachable*. It is **project-bound**: its contents live on that project and do not flow to the organisation's workspace or org context, and the project owner holds an audited override to view it (ADR-0018, refined Session 3). The **workspace sandbox**, by contrast, is part of the organisation's own workspace environment and is absolutely private — no project owner can reach it.

**Consequences:** The reachable-channel set is a function of the environment a request runs in, not of the user's identity alone, so confidentiality between a consultant's rival engagements is produced structurally: there is no environment in which A's grounded or guiding context and B's project coincide. Filter 1 of the distillation boundary stops being a separate rule and becomes a consequence — distilling into org context is a workspace request, and a workspace request cannot reach any project's channels, so no automated path absorbs one client's material into a portable store. (What this does *not* prevent is a Participant deliberately copying material it can read out of a project and into its workspace; that egress is a deliberate, audited act, defeated only as an automated or accidental leak, and is settled in ADR-0026.) The data model gains an explicit environment on every request — a project key or a workspace key — that scopes assembly before any store is read; assembly stays a per-request composition, never a persisted merge (ADR-0020). This defines the "own workspace, no project" case ADR-0020 omitted, makes the portable-versus-fixed split of the channels explicit, and confirms that sandbox privacy and channel reachability are orthogonal. It is the substrate ADR-0026 builds the distillation and egress boundary on. Builds on ADR-0018, ADR-0020, ADR-0021 and ADR-0022.
