# ADR-0045 - A project document ontology: a Uniclass/ISO-19650 classification vocabulary the owner owns, and first-class typed relationship edges between deliverables — colocated in Postgres, derived not duplicated, agent-proposed and human-confirmed

**Status:** Accepted. Refines ADR-0008 (gives the deferred per-project metadata schema a concrete shape — a classification vocabulary). Builds on ADR-0011/0021 (the grounded corpus and the channel model — this ADR adds structure *about* documents, it does not change *what grounds*), ADR-0022/0024 (retrieval: the access+state SQL pre-filter, and the colocated pgvector store), ADR-0013 (currency-by-state), ADR-0041 (ISO 19650). Produced by the ontology grill (2026-07-26, session O — record in [grill-history.md](../../grill-sessions/grill-history.md); its prompt file was removed 2026-08-04 once all three forks were ruled here).

**Context:** Infora had a **latent ontology it did not use**. [CONTEXT.md](../../../CONTEXT.md) already named "relationships to other documents" as authoring metadata, but the schema stored it as a shapeless `metadata` jsonb on the Container ([data-model.md](../../build/data-model.md) Drawer 2), and the per-project metadata schema had been deferred since ADR-0008. The domain is already relational — Deliverable plan → Container → Version → Rendition, the review cycle, supersede/withdraw edges, disciplines, work packages — but none of that structure was legible to a query or to an agent: the library was a flat list of coded containers whose only modelled inter-document relationship was lifecycle (`supersedes`). Two costs followed. First, an agent could not run the *structural* checks that prevent the industry's characteristic failures — duplicated work across producers, lost/orphaned drafts, stale grounding after a supersede — because those are graph questions, not similarity questions. Second, retrieval had only one gear: brute-force vector search over the whole corpus, which does not scale in cost or precision to a project library of 100k+ documents, and cannot answer purely structural questions (currency, coverage, dependency) at all. The hiflylabs analysis frames the general point — RAG retrieves text but has no model of how entities relate; an ontology gives agents a queryable model of organisational state and turns corpus-wide similarity search into scoped, often deterministic, traversal.

**Decision:** Introduce a **project document ontology** as a first-class concept, in two layers, plus the rules for who owns it and who writes it.

**1. A classification vocabulary (the schema layer).** Each project carries a controlled vocabulary that deliverables classify against — discipline, system/asset breakdown, work package, document type, project phase. It is **seeded by copy** at project creation from an Infora default grounded in **Uniclass 2015 / ISO 19650 breakdown structures** (cohering with ADR-0041's 19650 versioning) — a copy, not a reference, so one project's edits never rewrite another's, exactly as the acceptance-code scheme is seeded (ADR-0003). This gives ADR-0008's deferred per-project metadata schema its concrete shape: the `Container.metadata` jsonb becomes classification against a known vocabulary rather than a free bag. The recognised standard is load-bearing, not cosmetic — it is what lets a chartered engineer trust a classification (and therefore the agent's claims built on it) on day one, ending the "says who?" question that an Infora-invented taxonomy would invite.

**2. Typed relationship edges (the instance layer).** Cross-document relationships become **first-class, append-only, directional edges between containers** — `supersedes`, `references`, `responds-to`, `is-part-of`, `derived-from` — replacing "relationships to other documents" as free text. Edges follow currency-by-state like everything else (ADR-0013): nothing is deleted; a stale edge is retired, not removed.

**Ownership — the project-library owner owns the ontology.** One shared vocabulary per project, owner-authoritative, extended through the same negotiation the naming scheme uses (a producer proposes a value the default lacks; the owner folds it into the project-wide vocab, [CONTEXT.md](../../../CONTEXT.md)). **Not per-organisation:** the payoff is the owner's MIDP comparing like with like across producers, so cross-producer legibility wins at the classification layer. The ethical wall already hides *content*; a shared classification *skeleton* exposes no IP, and per-org vocabularies would fragment the portfolio view and force a translation layer between every pair of producers.

**Colocated, not a second store (Claude-owned mechanics).** The classification vocabulary and the edge tables live in the **colocated Postgres** (ADR-0024), as relational tables — *not* a graph database. This is the load-bearing infra choice: it keeps the access + state resolution as SQL **pre-filters in the same query** as vector search (ADR-0022), and the ontology simply adds **semantic pre-filters** (classification, edge traversal) to that same query. A separate graph store would split the wall-enforcing pre-filter across two systems — unacceptable given the wall is the product's core promise. The graph is **derived, not hand-maintained**: it is projected from the record (the Documents-view discipline — sensible defaults, no hand-built views, no drift), never a parallel source of truth.

**Who writes it — agent-proposed, human-confirmed.** Classification is **agent-proposed** at planning/promotion and shown on the container as an **editable field** the authoring team can correct (it rides the plan metadata that already exists). Relationship edges are **agent-proposed on promotion and human-confirmed** before going live — nothing structural is auto-written without a person in the loop. Cross-organisation naming is reconciled by KROMA-style ontology matching (org A's "flood study" is org B's "FRA"), which the shared owner-owned vocabulary makes tractable.

**Build-1 surface — agent-facing first, thin confirmation surface.** The ontology powers the checks and the retrieval pre-filter from day one, mostly invisibly. But the minimum surface is **non-zero**: a chartered engineer will not reorganise two teams' work on a classification they can neither see nor correct, so classification is a visible editable field and edges are accept/reject. A dedicated graph-explorer / ontology-management UI is a **later slice**, not build-1.

**What this does *not* change.** The ontology is structure *about* documents; it does not touch the grounding invariant. The classification vocabulary and the edges are **metadata and structure, never a grounded corpus** — they filter, organise, and enable traversal, but they are not cited claims and do not enter the grounded channel (ADR-0021's privacy invariant governs grounding unchanged). What grounds is still the project library, within project material (ADR-0011). Edges may *inform* provenance (a citation can carry "this source supersedes an earlier version") without themselves being citeable.

**Consequences:**

- **ADR-0008's deferred per-project metadata schema is closed** — it is a classification vocabulary seeded from a Uniclass/19650 default, owner-owned, extended via the naming-scheme pattern. The naming scheme and the classification vocabulary are now siblings under one owner.
- **The agent gains deterministic structural checks** that RAG cannot do — the moat play (retrieval + codified workflows): collision detection (two producers drafting to the same asset/work-package before either promotes), coverage/lost-work gaps (planned MIDP containers with no linked draft; unbound sandbox docs whose classification matches a waiting container — feeding the ADR-0038 binding transition), supersede-impact analysis (walk `references` edges to flag every document and past citation that grounded on a now-superseded version), and precedent surfacing (a new deliverable classified into a work package surfaces siblings, applicable standards and precedents through the guiding/grounded channels).
- **Retrieval scales past 100k docs.** A structural pre-filter (this discipline, this asset, current-state, this work package) narrows the candidate set *before a single embedding is compared*, collapsing a corpus-wide ANN search into a scoped one — the single biggest cost/precision lever, and it reuses the ADR-0022/0024 same-query pre-filter seam. Purely structural questions ("which structures deliverables are overdue / superseded / unreviewed") are answered from the graph with **zero retrieval and provable correctness**.
- **New terms to mint in `CONTEXT.md`** (follow-on): Classification vocabulary (or Project ontology), Classification, Relationship edge (with the edge type set), and the T-Box/A-Box distinction if useful. Component-5 §2/§8 and `data-model.md` Drawer 2 gain the classification vocabulary and edge tables (a new drawer or an extension of Drawer 2) when the slice is built.
- **A later slice owns the graph-explorer UI** and richer relationship views; build-1 stays agent-facing with the thin confirmation surface.
- Sits alongside ADR-0011/0021 without superseding them; refines ADR-0008; extends the ADR-0022/0024 retrieval architecture with a semantic pre-filter.
