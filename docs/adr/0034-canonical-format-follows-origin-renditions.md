# ADR-0034 - Canonical format follows origin: uploaded files stay native, authored documents are Infora structured text; renditions are stored, immutable, one-way exports

**Status:** Accepted (owner-ruled 2026-07-18, Slice A design session). Refines ADR-0002, 0004, 0032. Benchmarked against Legora's Editor (internal AI-native format, "exports directly to Word in the style of your choice", Word add-in as a separate complementary surface — [reference](../reference/legora-ui-review.md)).

**Context:** The tracker carried the canonical-format decision ("markdown vs rich/structured — decide once, at whichever of Slice A/B lands first") and the owner's requirement that the Editor produce Word and PowerPoint documents, with PowerPoint being a differently-shaped document, not just a rendition. Ruling it surfaced the real structure: documents reach the sandbox by two routes — dragged in from the Office world, or created in Infora's editor — and neither should be forced through the other's format.

**Decision:** **A sandbox document's canonical format follows its origin.** An **uploaded** document (drag-and-drop from Word/Excel/PowerPoint) keeps its **native file as canonical** — stored as-is, viewable through a rendered PDF, attachable, promotable and reviewable, but not edited by Infora's editor. An **authored** document (created in the editor) has **Infora's structured text as canonical** — the substrate the AI machinery (suggestions, grounding, citations, anchors) operates on — and carries a `kind` (`text` | `slides`): a slide deck is a differently-shaped document in the same substrate (slide-delimited sections), not a rendition trick.

**Renditions are stored, immutable, one-way exports.** A Rendition row binds to its Version: `kind` (`native` — the asset the client owns and reuses | `pdf` — the review-and-record rendition, ADR-0004) and `format` (`docx` | `xlsx` | `pptx` | `pdf` now; the dwg/CAD class is deliberately deferred). For an authored version the native rendition is generated at promotion (house styles applied at export — future config); for an uploaded version the native rendition *is* the file, with the PDF derived. A rendition is a snapshot of the record and never an editing surface.

**The bridge is a deliberate conversion.** When an uploaded document needs AI-assisted drafting, "Open in editor" converts it to authored **in place**, the original file preserved in the ambient history — honest about fidelity: complex Word formatting may simplify, and the user chooses. The reverse path never exists (authored documents export; they do not convert back). **Meeting users where they are is sequenced, not forked:** the Infora editor is the v1 authoring surface; the Word add-in (Slice B) serves the native-docx population — AI suggestions as tracked changes on the user's own file in Word, through the same API — so neither route converts against the user's will.

**Consequences:** `format` is per-version, so one container may legitimately carry an uploaded-docx v1 and an authored v2; review is unaffected because comments anchor to each version's frozen PDF regardless of source format. Excel and future CAD deliverables are first-class library citizens without Infora pretending to author them. The editor's WYSIWYG ambitions stay bounded by one substrate instead of a docx round-trip. Sandbox document gains `origin`, `kind`, `format` and a file reference; Version content is a text snapshot or a file snapshot by origin; the Rendition table enters Drawer 2. Builds on ADR-0002, 0004, 0011, 0032.
