# ADR-0011 - The project library is the project's grounded corpus; owner-curated; auto-admits accepted deliverables; decouples WIP storage from knowledge

**Status:** Accepted. Refined by ADR-0021: the grounding invariant generalises from "the project library is the *sole* grounded corpus" to privacy — any non-private corpus may ground, and the authority corpus (legislation, policy, standards) is a second grounded corpus alongside the library. The substance below stands: within *project* material, still only the library grounds (never the sandbox or DRR). **Further refined 2026-07-06:** the library may be presented flat or foldered per project configuration (see the ADR-0016 note); access stays per deliverable, never per folder or section.

**Context:** "AI knowledge layer" was doing double duty. Drafting assistance wants a user's messy working context; knowledge retrieval must not ground on unfinished drafts (wrong content) or the DRR (review opinion, not fact). A trust line was needed. The sandbox-versus-SharePoint-mirror question hinged on the wrong assumption that the AI grounds on the sandbox.

**Decision:** A project has a project library: the curated, owner-controlled corpus of trusted project knowledge. It is the real-world MIDP generalised beyond transmitted deliverables. Accepted deliverables enter the library automatically on acceptance, since acceptance is already the trust decision. The owner may also add other material (reference documents, standards, baseline data) by deliberate action, and shares deliverables with named organisations per deliverable, so visibility is default-deny and owner-defined: a deliverable is seen only by the owner organisation, its author, and organisations the owner has shared it with. The library is a flat collection of coded deliverables, not a folder structure; access is decided per deliverable, never per section. Both AI purposes ground on the library for project fact: the chat agent answers project questions from it, and the Word drafting agent grounds new text on it; both may additionally cite the authority corpus for external authority (legislation, policy, standards), the grounded channel's second, public corpus (ADR-0021). What they never ground on is private or untrusted material: the raw sandbox, the DRR, and org or programme context (ADR-0020). The general rule is privacy — non-private corpora may ground, private context only informs (ADR-0021) — and "only the library, within project material" is the project-side case of it. The DRR remains a workflow surface the AI operates on as a task (clustering, drafting candidate responses, flagging duplicates), never a knowledge source.

**Rider (2026-08-27, the document-status session) — library membership is now necessary but no longer sufficient.** This ADR's rule was one condition: in the library, therefore grounded. It is now **three**, and only the first is this ADR's: in the library, **and** record state `live` (ADR-0013), **and** admitted by an acceptance code the project has marked as grounding (ADR-0003). The reason is that the 2021 National Annex makes published status codes stage-agnostic and leaves each code's meaning to the project's own information standard, so "accepted" alone no longer identifies what may be relied on. Nothing here weakens the ADR's own position — the sandbox still never grounds, and acceptance is still the trust decision that admits a deliverable to the library. What changed is that admission and groundability stopped being the same event.

**Consequences:** Trust comes from a curation decision, not from file location. Work-in-progress storage (native Infora sandbox or SharePoint mirror) is decoupled from knowledge quality, because the AI never grounded on the sandbox; it becomes a product and adoption choice, not a build-1 knowledge blocker (closes the open part of the sandbox-mirror question). A mid-draft document is invisible to the knowledge layer simply because it is not in the library; if an owner wants a not-yet-accepted document to be groundable, they add it to the library rather than us inventing a second trust flag. Per-deliverable sharing, default-deny, ties into the access model and ethical walls. Builds on ADR-0005 (acceptance) and the access model.

**Addendum (2026-09-06, owner-ruled, the app-builder design session — [ADR-0056](0056-the-app-model.md) §9).** *In plain terms: an app in the Tools section may read a tracker sitting in a sandbox its viewer is already in, and show a dashboard over it, without breaking the rule above.* The clause, as ruled: **An app reading a sandbox file its viewer can already open, and computing over it, is not grounding. Grounding is an Infora agent relying on material to state a fact in a draft or an Ask answer. The rule above governs that and only that. An app's insight over a sandbox tracker is a display of the viewer's own working data; it enters drafting only if a person files it into the record through the record's normal doors, which ADR-0056 §9 requires.** Two things the clause deliberately does not do: it does not let an app read a sandbox the viewer is not in, because an app acts as its viewer (ADR-0056 §4); and it does not let an app's insight become a citation, because the insight is a row in an app table and app tables are outside the agent's reach until a person attaches one to a single Ask question. ADR-0021's 2026-09-04 addendum draws the same line for surfaces; this sentence is the sandbox's own. Nothing above this line changes.
