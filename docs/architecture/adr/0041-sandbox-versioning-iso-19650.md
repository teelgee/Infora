# ADR-0041 - Sandbox document versioning: a v0.x working series in the sandbox, P (preliminary) on formal issue or promotion, C (contractual) on client acceptance

**Status:** Accepted (owner-ruled 2026-07-25, sandbox-structure build session). Refines ADR-0032 (the P-rev/C-rev convention, freeze, ambient history) and ADR-0034 (renditions). Builds on the immutable-version rule (T-008, ADR-0013: `versions.version_reference` cannot change; only `is_current` may).

**Context:** Sandbox documents had no visible version numbers, and the two Version series ADR-0032 named ("the freeze series and the plan container's issued series") were both numbered informally — freeze wrote `P{n}`, promotion wrote `v{n}` — with no relationship to ISO 19650's revision codes (P = preliminary/work-in-progress, C = contractual/shared-and-published). The owner wants a real scheme the producing team recognises: working drafts run v0.1, 0.2, 0.3…; a version becomes a P or C revision when it leaves the informal sandbox.

**Decision — one working series, two issued series:**

**1. Whilst in the sandbox, a document runs the working series `v0.x`.** Every ambient save-snapshot is a working revision — `v0.1` the first, `v0.{n}` the current head (ADR-0032's ambient history). A **plain check-out freeze** (ADR-0032 addendum, T-180) freezes the current working revision under its own `v0.x` number: it is still sandbox-internal, not an issue.

**2. `P{NN}` — the preliminary issue.** A version earns a P revision (two-digit, per container) the first time it is **issued into a formal review cycle or promoted**: a freeze that opens an internal sandbox-scope round issues `P01, P02…` on the freeze container; a promotion issues `P01, P02…` on the library container (each client-review round a further P). "Promoted without review" is still `P01` — promotion is the issue event, review or not.

**3. `C{NN}` — the contractual issue on client acceptance.** When a client (project-scope) review cycle is **accepted**, the deliverable is authorised and published: acceptance issues the **contractual `C{NN}` revision** of the accepted content. Because `version_reference` is immutable (T-008/ADR-0013), C is a **new immutable Version** carrying the accepted content, made `is_current` — not a relabel of the accepted P. Retrieval, the library, the plan and renditions all key on `is_current`, so they read the published C revision with no further change; the reviewed P revisions keep their references as the record of each round. A sandbox-scope (internal QA) acceptance never issues a C — it is producer-private evidence, never contractual (ADR-0032).

**Consequences:** Freeze, promotion and acceptance assign references by phase, at issue, immutably. The sandbox document read carries a `workingRevision` (`v0.x`, resolved from the ambient count) and the ambient history carries `v0.x` per snapshot; the sandbox surface shows the working revision on each row. The freeze series and the issued series stay the two independent sequences ADR-0032 named — now ISO-19650-coded. **Consequence of the immutable-version rule:** a contractual acceptance adds one Version row (same content as the accepted P), which the idempotent ingest sweep indexes like any other; grounding stays single-current by `is_current`. ~~**Deferred:** suitability codes (S0–S7) and the full ISO 19650 status matrix beyond the P/C revision letters; a per-issue suitability is a later refinement on this substrate.~~ **Superseded 2026-08-27 — see the amendment below; that sentence is also factually wrong about the code set.**

**Amendment (2026-08-27, the document-status session) — the deferral is discharged, and three corrections.**

**1. The term is `status code`, not "suitability".** "Suitability" is the older BS 1192 / PAS 1192-2 word for what a status code *expresses*; the current National Annex calls them status codes, and so should we ([iso-19650.md](../../reference/iso-19650.md)). **And the code set is not S0–S7.** The **2021** NA has `S0`–`S5` and `A1, An…`; `S6`, `S7` and `CR` were removed, `B1`/`Bn` deprecated, and the 2018 `S5` (which meant *withdrawn*) was reused for appointing-party acceptance. ⚠ Most free ISO material online — including the current edition of UK BIM Framework Guidance Part C, whose Edition 2 was never published — still reproduces the 2018 table without saying so. The codes now live on the acceptance-code scheme (ADR-0003, as amended), where they are the project's to extend.

**2. `S4` and `S5` are two gates by two parties, and they validate the two review scopes this build already has.** The National Annex separates **authorization** by the lead appointed party (`S4`, cl. 5.7.1) from **acceptance** by the appointing party (`S5`, cl. 5.7.3), and *"only after both does a `C`-revision `An` container exist."* The 2021 NA introduced `S5` **precisely because industry was collapsing the two into one code** — which is the failure the promotion-requires-QA setting guards against (ADR-0032 addendum, 2026-08-09 S9). So §3's rule above — *a sandbox-scope acceptance never issues a C* — is not an Infora convention but the standard's own position: internal QA authorises, the client's cycle accepts, and only the second is contractual.

**3. One divergence, now deliberate rather than accidental.** ISO's revision code is three-part — `P01.02`, where the two digits after the point are the **WIP version of that primary revision** — whereas §1 above runs a separate `v0.x` working series before the first issue. The owner ruled `v0.x` on 2026-07-25 for recognisability, against a picture informed by the 2018 material; it is **retained**, and recorded here as a conscious deviation so nobody later reads it as a misunderstanding. The two carry the same information: a working revision before any issue, and an issue that supersedes it.

**Addendum (2026-07-25, ADR-0043 — the co-authoring substrate):** a WOPI `PutFile` save boundary writes a `v0.x` ambient working revision like any other save, so co-authoring in Office folds cleanly into this working series; the P/C issue rules at freeze / promotion / acceptance are unchanged. Durable native-file version retention (keeping prior file blobs, not just text snapshots) arrives with the WOPI host — Slice A3 P2.
